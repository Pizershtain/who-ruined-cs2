# M4.4 backend hardening

M4.4 keeps the application local-only and leaves scoring, public DTOs, the
database schema and the frontend unchanged. It adds finite admission and read
budgets around the existing M4.3 lifecycle.

## Runtime policy

- Native API default bind: `127.0.0.1`. Compose publishes only
  `127.0.0.1:${API_PORT}:3000`; the worker publishes no port.
- Browser state-changing requests with an `Origin` header are accepted only
  from `API_CORS_ORIGINS`. This is a local browser safeguard, not authentication.
- The active participation policy remains server-owned. Every HTTP `policy`
  selector, including encoded, repeated and array spellings, returns
  `422 INVALID_POLICY_SELECTOR`.
- Uploads have a finite in-process concurrency limit and a finite SQLite queue
  limit. Saturation returns `429 UPLOAD_BUSY` or `503 QUEUE_SATURATED` without
  creating a second retained upload.
- Request URLs, JSON bodies, headers and server wait times have explicit limits.
  Every application response has a correlation request ID and safe headers.

## Canonical result budgets

Canonical and legacy gzip readers independently limit compressed bytes,
inflated JSON bytes and JSON nesting depth. SHA-256 and schema checks still run,
and a canonical artifact must bind its match, active rating and recompute seed
to the same SQLite match ID. Corrupt, truncated, oversized, stale or cross-match
content is never returned as partial JSON.

Defaults are intentionally conservative local budgets:

| Variable | Default |
| --- | ---: |
| `MAX_RESULT_COMPRESSED_BYTES` | 8 MiB |
| `MAX_RESULT_JSON_BYTES` | 64 MiB |
| `MAX_RESULT_JSON_DEPTH` | 128 |
| `MAX_CONCURRENT_UPLOADS` | 2 |
| `MAX_QUEUED_JOBS` | 32 |
| `MAX_JSON_BODY_BYTES` | 128 KiB |
| `MAX_QUERY_STRING_BYTES` | 8 KiB |
| `API_REQUEST_TIMEOUT_MS` | 30 minutes |
| `API_HEADERS_TIMEOUT_MS` | 15 seconds |

Docker additionally applies memory, CPU and PID limits plus
`no-new-privileges`. Those limits reduce local blast radius; they do not turn
the service into a public-hosting security boundary.

## Verification summary

An isolated Docker project exercised real demo upload, completion, canonical
and active reads, SHA dedup, restart, deletion, corrupt-gzip rejection, the
exact 512 MiB upload boundary and concurrent-upload backpressure. Owner-only
H2 → H1 → H2 rebuilds returned to H2 with zero rating error in the exercised
HTTP profiles; policy mismatch failed closed with 409. Forty GETs racing DELETE
all returned complete JSON. Forty active-rating GETs racing rebuild returned
only complete H2 responses or typed 409 responses, never torn JSON or 5xx.

M4.4 originally retained the default-off P2/C2+S2 compatibility route pending
an owner decision. M4.5 records that decision and removes the route, its public
DTO and its feature flag without changing the hardening controls above.
