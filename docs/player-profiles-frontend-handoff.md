# Player Profiles и частичные данные

## Подключение

Profiles запускается отдельно. Браузер обращается к относительным путям `/api/v1/players/…` через тот же Gateway, который обслуживает Web. Адрес по умолчанию `http://127.0.0.1:5173`. Порт 3001 предназначен для локальной диагностики. Секрет публикаций используется только между Profiles и Core. [Маршрутизация Gateway](api-gateway-and-service-layout.md#routes).

| Запрос | DTO | Что отдаёт |
| --- | --- | --- |
| `GET /players/:steamId/profile` | `playerProfileSchema`, `player-profile@1` | Последний подтверждённый ник, результаты, метрики, H3, награды и средние Radar |
| `GET /players/:steamId/profile/matches?limit=20&cursor=…` | `playerProfileHistorySchema`, `player-profile-history@1` | История матчей и наград, рейтинг каждого матча, данные каждой метрики и курсор |
| `GET /ready` на диагностическом порту | Поля `status`, `sourceOnline`, `feedCaughtUp`, `pending`, `retrying`, `lastReadAt` | Текущее состояние синхронизации для локальной диагностики |
| `GET /matches/:matchId/measured-stats` **на Core** | `matchPublicationStateSchema`, `match-publication-state@1` | Независимые измеренные данные H3-матча. Можно подгружать даже при выключенном Profiles |

Точные DTO и парсеры находятся в `@who-ruined/contracts`. `steamId` остаётся строкой. Проверять его через `profileSteamIdSchema` и сопоставлять профиль и строки с запрошенным ID. Для неизвестного профиля summary отдаёт 404 `PROFILE_NOT_FOUND`, history — пустой список. Некорректный ID или параметры дают 422. При выключенном сервисе старые страницы матча продолжают использовать Core.

### Навигация и история

- В существующем отчёте игрока добавить ссылку на постоянный профиль при валидном SteamID64. Для анонимных участников ссылка на отчёт матча сохраняется. Внешняя ссылка на Steam строится из подтверждённого ID.
- В заголовке профиля показать `displayName`. В истории использовать `player.displayName`, записанный для этого матча. Одинаковые ники не объединять.
- Отдельно показывать `playedAt` и `uploadedAt`. Если первая дата null, показать дату с пометкой «Загружено». Форматировать через `Intl`.
- История уже отсортирована по дате и ID. Запрашивать следующие страницы по непрозрачному `nextCursor`, не вычислять курсор в UI. `limit` от 1 до 50. Каждый матч предоставляет `matchId` и `player.playerId` для ссылки на существующие `/matches/:id` и `/matches/:id/players/:playerId`.
- Исход `UNKNOWN` обозначает неизвестный результат. В win rate включены подтверждённые победы, поражения и ничьи. Для истории вывести карту, команду, исход, основные метрики, награды и доступность рейтинга.

### Отображение накопленных данных

- Основные показатели и раунды брать из `measurements`. Для ADR, K/D, KAST и Radar использовать серверный `value`. KAST и win rate сервер возвращает в процентах. В истории `numerator` — подтверждённое измерение, для отношений нужен `denominator`. Для KAST умножить вычисленное отношение на 100 для отображения или показывать подтверждённые раунды KAST в числителе. При знаменателе 0 процент или отношение не выводить.
- Четыре состояния метрики — `AVAILABLE`, `PARTIAL`, `UNAVAILABLE`, `NOT_APPLICABLE`. Доступный ноль выводить числом. У частичного значения показывать покрытие рядом с ним. Например, «ADR 78,4 · 22/24 раундов» или «3/4 матча». Если точное количество раундов неизвестно, показывать известное покрытие по матчам и общую пометку о неполноте. Поле `applicableMatches` исключает неприменимые матчи.
- Верхний блок итогов включает агрегаты MVP, Who Ruined и EVP. `null` в записи матча означает, что решение или источник недоступны. `false` либо пустой массив специализаций означает, что сохранённый применимый результат не присудил награду этому игроку. Подсветка в UI берётся из сохранённых результатов.
- График рейтинга группировать по `policy.id` и `policy.digest`. Для текущих профилей доступны значения H3 и вклады семи семейств. Серия с `rating:null` имеет пропуск. H2 исключён из профилей по решению владельца. Если Core отдельно отображает старый матч, его H2-отчёт остаётся самостоятельным представлением.
- Агрегаты восьми осей Radar сгруппированы по `normalizationVersion`. Не смешивать значения разных версий. В интерфейсе можно сохранить текущие семь видимых осей, а задачи карты показать в статистике. Для геометрии использовать соответствующий versioned registry Radar и только подтверждённое значение. Пропуски осей не закрывать нулём. На странице матча оставить существующий Radar с его полями атрибуции.

### Состояния и проверка

Показывать состояние загрузки при первом запросе. Ошибка профиля не блокирует отчёт матча. При обновлении держать последнюю доступную проекцию и дать повторить запрос. Если `ready` сообщает о синхронизации, показать компактный статус и сохранить доступные метрики. Новые тексты и доступные имена проводить через Locale Kit. Таблицу истории проверить на мобильной ширине, в RTL, с управлением через клавиатуру и настройкой уменьшенного движения. Ошибки и заполненность не кодировать одним цветом.

Для тестов используйте [синтетические ответы Profiles](examples/player-profile-mixed-data.json). Они содержат подтверждённый ноль, частичный ADR, неизвестный результат и смену ника. Прогоните отдельно недоступность сервиса, 404, пустую историю и следующий курсор.
